## 先看要做出个什么东西

深夜十一点，你在购物 App 里敲了一句「昨天买的耳机怎么还没发货」，几秒钟后回复来了，带着订单号和最新的物流节点，屏幕那头未必是熬夜值班的客服，多半是个 AI。

![](<images/学习攻略：11 天怎么走-test-3.jpg>)

这门课带你从零到上线，亲手做出这么一套东西：一个生产级的电商 AI 智能客服系统。用户问商品参数，它要答得上来。查订单、追物流，就得真去数据库和 API 里翻，还只能翻这位用户自己的单子。退款售后，政策怎么写就怎么办，不能让它拍脑袋乱承诺。万一碰上投诉，就别让它硬接，赶紧转给人工。



先带你看一眼这套系统的全景，就看一条用户消息进来之后走的这趟旅程。还是刚才那位半夜等发货的用户，物流答完，他又追了一句「它能退吗」，系统先得弄清「它」说的是那副耳机，再判断这句话到底想干什么：查政策？要退货？还是纯闲聊？



来意不同，走的路也不同。问政策、问商品知识的，先去知识库把相关条文检索出来。查订单、追物流的，交给 Agent 拿着工具去业务库里翻。答案出来之前，系统还要自己掂量一下有没有把握，有把握就回给用户，没把握就换成兜底话术，必要时转人工。



最妙的是收尾这步：没答好的问题不会白白溜走，攒起来经人工审核补进知识库，下次再被问到就能答上了，客服就这么越用越聪明。说到底，智能客服就是个数据工程：模型和框架谁都能用，真正拉开差距的，是这套数据循环是否闭环，能否越跑越好。

![](<images/学习攻略：11 天怎么走-test-2.jpg>)

把这趟旅程拆开，每一站都是 AI 应用开发里的一个关键难点：RAG、工具生态（Function Calling / MCP / Skill）、Workflow + Agent 混合架构、会话上下文管理、模型微调、可观测性、数据飞轮，面试里被问烂的这些词，在这门课里都会长成同一个项目里活生生的模块，串成一条能上线、也能写进简历的主线。

![](<images/学习攻略：11 天怎么走-test-1.jpg>)

## 技术栈长什么样

先说主线：Python 写业务，FastAPI 做 Web 框架，AI 这一层交给 LangChain 和 LangGraph，为什么围着这几个框架转？说白了，它们就是眼下 AI 应用开发的主流，生态全、资料多、面试官也熟。在课里围绕它们把每个能力做透，出去就能直接上手干活。



存储层是 MySQL，ORM 用 SQLAlchemy，都是后端同学的老熟人，前端有一个用原生 HTML + CSS + JavaScript 写的对话界面，但不单独成章，只是为了方便调试和演示。

![](<images/学习攻略：11 天怎么走-test.jpg>)

各章具体用到什么，下面这张路线图先混个眼熟。每一项到了对应章节都会讲清「为什么选它、跟备选怎么权衡」，现在不用记：

## 第一阶段：看懂全貌

本阶段的目标是花一天时间建立对整个项目的宏观理解，搞清楚「我们到底要造什么、为什么要造它」。材料就在你手上：这篇攻略，加开头那条导学视频。



上面「先看要做出个什么东西」那一节就是全景：一条用户消息进来，系统先弄清「它」指的是哪件商品哪笔订单，再判断来意，问政策的去知识库检索，查订单的交给 Agent 拿工具去翻，答不上来的不硬答，攒进数据飞轮等人工审核补库。六分钟的导学视频把成品真跑起来的样子演了一遍。



这个阶段顺手把环境装好：照着本文下面挂的「环境准备」，把 Claude Code、Superpowers 插件、git worktree 三样备齐，源码从「源码下载」取。



它的面试价值在于：当面试官说「聊聊你这个项目吧」，你能用三十秒讲清楚 MewHelp 是什么、解决了什么问题、你为什么要做它。这三十秒比后面三十分钟的技术细节都重要。

## 第二阶段：吃透骨架

本阶段对应专栏[第 1 章](https://icnaxnmh86kx.feishu.cn/wiki/ZDQBwxjMBieHS4kuuQpcZcDnnoh)到[第 6 章](https://icnaxnmh86kx.feishu.cn/wiki/DEdswmIhuiqgL1kGZxIcrRz4nEb)，是整个课程的核心骨架，也是面试中被追问最多的部分。这六章遵循「从基础到复杂、从单模块到全链路」的逻辑，一步步把一个生产级智能客服的核心引擎搭起来。



第 1 章让程序跟大模型说上第一句话：接上 LLM、把 Prompt 做成可维护的模板、跑通流式输出。第 2 章给 AI 装上手脚，定义查订单、查物流、搜 FAQ 这批业务工具，项目骨架和数据库也在这章搭好。第 3 章解决「答得准」：你会先亲眼看到关键词查表怎么翻车，再把知识变成向量、按意思去找，跑通建库和问答两条完整链路。第 4 章往深水区走，混合检索、重排、评估体系，这是 RAG 面试问得最深的地方。第 5 章是全课的承重墙，用 LangGraph 把 Workflow 的确定性骨架和主力 Agent 的灵活收敛拼成一副生产级架构。第 6 章补上分流的脑子：意图识别、指代消解，以及退款这类不许模型自由发挥的确定性子流程。



如果你是初次接触，不用强求一次吃透所有细节，先把每章的架构设计和设计决策理解到七成以上就可以继续推进。建议后续反复回看本阶段的内容，尤其是 RAG 两章和混合架构这三章，通常需要精读三次以上才能在面试中流畅输出。



面试官在这个阶段最爱问的问题包括：为什么关键词检索不够、要上向量？混合检索和重排各解决什么问题？Workflow 和 Agent 怎么分工、为什么不全交给 Agent？用户没报订单号系统怎么处理？每一个都是高频考点。

## 第三阶段：解锁进阶

本阶段对应专栏[第 7 章](https://icnaxnmh86kx.feishu.cn/wiki/RSmgwPpjYiMIYOkbyZCcAPwwnGe)到[第 10 章](https://icnaxnmh86kx.feishu.cn/wiki/VuAIwDc85iNBllks7T7c8YoQnwe)，核心目标是让 MewHelp 从「能跑」变成「能运营」。如果说第二阶段搭的是系统的骨架，这个阶段就是给骨架装上肌肉和神经系统。



第 7 章解决记性问题，让客服在一通对话里记得住前面聊过什么，滑窗、摘要、token 预算都在这章。第 8 章把工具扩成一套生态，外部工具经 MCP 协议即插即用，配上超时、重试、审计日志这些工程配套。第 9 章上可观测和数据飞轮，每一步调了什么工具、检索回了什么、花了多少 token 都看得见，答不上来的问题攒起来人工审核补进知识库，系统越用越聪明。第 10 章讲模型微调，重点是想清楚到底该不该微调、微调什么，再用一个主题分类器把数据处理到训练评估的全流程走一遍。



这个阶段每一章都是一个独立的能力模块，时间紧张可以根据面试需要有选择地精读。它们的价值在于展现你对 AI 应用的纵深理解：大部分候选人只能讲清楚 RAG 检索，但你还能讲可观测怎么做、飞轮怎么闭环、什么时候才轮到微调，这就是差异化竞争力。

## 面试核心目标

对于目标是面试的同学来说，学会把有限的时间和精力投入到最具产出的环节至关重要。



### 面试简历

学完课程之后，下一步就是把项目写进简历。一份好的项目经历要把三件事讲清楚：



**项目介绍**：一两句话说清楚项目是什么、解决了什么痛点。面试官扫简历的时间很短，开头不抓人后面就不会看了。



**个人职责**：分点写你负责了哪些模块，每一点带上具体的技术或解决的问题，避免写空泛的描述。



**技术亮点**：分点写最有技术含量的设计，关键技术名词加粗。每个亮点一句话说做了什么，一句话说效果。这是面试官最容易追问的地方。



简历怎么写、项目怎么介绍、高频题怎么答，第 12 章都备好了：[简历模板](https://icnaxnmh86kx.feishu.cn/wiki/GL5Lwd3eFiqVU7kYJF4cYd42nce) · [如何介绍你的项目](https://icnaxnmh86kx.feishu.cn/wiki/MVv5wLr0mivaGakw7UXc3FEwnpc) · [面试题](https://icnaxnmh86kx.feishu.cn/wiki/Ljd0wgFK3iAJiXkb7utcDQC2nRb)。建议把项目名称换成自己的，避免简历撞车。



### 可以放后面

源码解读对深度理解非常有帮助，但如果时间紧张，可以优先保证架构设计的理解。先吃透设计，代码可以后补。



实战篇教的是用 Claude Code 加 Superpowers 流程把整个项目一步步长出来，能大幅加深理解，AI 协作开发本身也是当下很热的加分能力。但它不是面试的硬性要求，时间紧张可以先跳过，拿到 offer 再补也不迟。

## 常见问题解答

### 章节太多看不完怎么办？

十二章确实不少，但并不是每一章都需要投入相同的精力。如果你的时间非常紧张，核心要保住的是三块内容：本文开头的项目全貌、第 3 章到第 5 章的 RAG 和混合架构（这是面试必问）、第 11 章和第 12 章的复盘与面试指南。这几块加起来大概 4 天就能吃透，足以支撑一场完整的面试。剩下的章节可以按面试题里的考点倒推，哪个题答不上来就回去补哪章。

### 代码需要自己写一遍吗？

不需要强求。课程提供了完整的 Python 源码，直接下载就能阅读和运行，理解架构设计和设计决策比手写代码更重要。这门课的实战篇走的是另一条路：你不敲代码，用 Claude Code 加 Superpowers 流程把项目一步步长出来，方向和验收由你把关。时间充裕强烈建议走一遍，对项目的理解会有质的提升；短期冲面试的话，把时间花在理解设计和练习口述上，性价比更高。

### 理论篇、实战篇、源码解读该怎么搭配？

每章的理论篇是主线，讲概念原理和选型权衡，面试要的东西都在这里。实战篇带你用 AI 把这一章真正造出来，时间充裕再做。源码解读把最终代码系统走一遍，想抠实现细节再看，跳过不影响后面的章节。速通线就是：只读理论篇，读完直接进第 12 章。
