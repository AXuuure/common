## 1. 用法分流：这本书 95% 不能当 L3 素材

架构教科书绝大部分是已经坍缩的 hard label。直接"重走一章"就是读书笔记，正是你方法论第 1 节要防的行为克隆。正确拆法：

```
                 凤凰架构的内容分层
                        │
   ┌────────────────────┼─────────────────────┐
   ▼                    ▼                     ▼
各章正文结论         "我们用了X/不推荐Y"     作者的写作决策本身
（分层/共识/容错…）   的每一段               （为什么这么编排、为什么砍掉某方案）
   │                    │                     │
   ▼                    ▼                     ▼
  L1 四层卡            L2 三问                L3 链路 A ← 唯一能"先决策后对照"的矿
  可引锚点             随手用                  重走作者决策 + 读者侧选型重走
```

**判据**：一段内容能不能跑 L3，看它有没有**当时可见的信息集 + 真实岔路 + 选错有代价**。教科书的"K8s 三种网络方案对比"没有前三样（那是清单不是岔路）；但"作者为什么把可观测性砍成两章而不是六章"有。

## 2. 三条候选链路

### 链路 A · 作者侧（首选，负向推理密度最高）

对象：周志明作为这本书的作者，2018→2026 怎么把它做成现在这个形状。

| # | 岔路 | 节点性质 | 素材预判 |
|---|------|----------|----------|
| A1 | 为什么主轴是"**可靠**"而不是性能/成本/DDD | **重灾区**：负向推理——它在否定哪条主轴 | 前言/序有自述概率高 [待挖] |
| A2 | 为什么做在线免费 GitBook + 开源仓库，而不是只出纸书 | 放弃版税换传播？约束是什么 | 待挖（博客/访谈） |
| A3 | 五种架构风格为什么恰好是 Spring Boot / Spring Cloud / K8s / Istio / Lambda | **重灾区**：为什么没有 DDD 分层单体、没有单元化、没有 SCA | 章节编排 [实测] + 理由 [素材不可判]风险高 |
| A4 | 同一个 Fenix's Bookstore **重写五遍** vs 一个渐进演进项目 | 教学机制决策，对应你 dsh 主线 | 待挖 |
| A5 | 为什么把"不可变基础设施"提升为一级部分而非并入 K8s 章 | 抽象层次选择 | 待挖 |
| A6 | 2024–2026 的在线版修订：**他自己推翻了哪些结论** | **重灾区**：作者公开改判是全书最硬的思维链素材 | GitHub commit 历史 [实测可挖] |
| A7 | 分布式共识（Paxos/Raft）写进正文 vs 只给指引 | 深度 vs 广度的取舍 | 待挖 |

> A6 是这本书区别于任何纸质书的独家矿：**版本历史 = 一位资深架构师 2021→2026 判断变化的原始记录**。挖 A6 之前先建 commit 索引（哪些章节被重写、增删行数、提交说明），别读正文就下结论。

### 链路 B · 读者侧选型重走（次选，退化风险最高）

把"演进中的架构"那章还原成年份现场：只给**当年可见的技术和约束**，你在现场做决策，读完你的答案才对照书的结论。

| # | 年份现场 | 当年约束（信息集要点） |
|---|----------|------------------------|
| B1 | ~2000 单体 + 集中式数据库 | 并发上来：scale-up 还是拆？当时集群中间件什么水平 |
| B2 | ~2005 垂直/水平拆分 | LAMP 成熟期，SOA 正被热炒 |
| B3 | ~2008 ESB/SOA 上不上 | 拒绝什么、代价是什么 |
| B4 | ~2014 微服务拆不拆 | Netflix 案例可见，DDD 尚未与微服务合流 |
| B5 | ~2016 容器 vs 虚拟机 | K8s 刚开源，编排格局未定 |
| B6 | ~2018 自运维 K8s vs 买托管 | 你的团队规模是约束 |
| B7 | ~2019 mesh：治理下沉 sidecar 还是留 SDK | Istio 0.x，性能代价有争议 |
| B8 | ~2021 serverless：什么场景反转回容器 | 冷启动/厂商锁定可见 |

**这条最大的坑**：B1–B8 的正确答案都在书里写着，AI 制作时知道结局、你也大概率听说过结论 → 极易退化成"背结论"。防线两条：① 第一问严格开放式（**禁选项**，v0.2 铁律）；② 岔路后果由 AI 从**当年可见约束**推，标 [推断]，不许借 2026 年的行业共识判你。

### 链路 C · 你自己的处境（迁移题的固定答案池，不单独立卡）

| # | 你的岔路 | 咬合点 |
|---|----------|--------|
| C1 | ChorusTavern 现在到没到"架构性临界点" | 用书中判据自检，不达标就不该拆 |
| C2 | 拆服务 or 不拆的依据 | 对应 B4 的迁移段 |
| C3 | 治理走 SDK（Spring 生态惯性）还是 sidecar | 你是 Java/Spring 团队，这是真实岔路 |
| C4 | 可观测性预算：你团队付得起哪一档 | 对应"透明多级分流"部分 |
| C5 | 一个 harness 承载多种架构风格的研究设计 | **对应 A4**——dsh 主线最硬的一条 |

C 段只出现在每张节点卡的"迁移题"里，不单独跑，否则会变成自我印证。

## 3. 目录与出卡规范（v0.2 双文件）

```
系统设计/凤凰架构/
├── 链路学习计划-凤凰架构.md        ← 本文件（制作人工作台）
├── 链路-A-作者决策链/
│   ├── 链路图.md                   含"vs"岔路，禁止外泄到题目文件
│   ├── commit索引.md               A6 的前置产物
│   ├── 节点卡-A1-主轴选择-题目.md   只含：信源/信息集/后见之明过滤/开放式第一问
│   ├── 节点卡-A1-主轴选择-答案.md   对照/专家思维链/机制归因/迁移题
│   └── 路径复盘.md                 分叉树 + 偏差指纹
└── 链路-B-选型重走/                （同结构）
```

**出卡四条硬规则**：
1. 题目文件**不得出现岔路选项**，选项挪到答案段作为"当事人当时的问题框架"复盘材料。
2. 制卡（AI）与跑卡（你）分离：AI 读正文和 commit，你只读题目文件。这是唯一能保证"AI 手里有答案但说不出"的结构。
3. 每个信息集必须附**后见之明过滤清单**（"2019 年的人不知道 mesh 会收敛到 Istio"这类），并显式列出 AI 知道但当事人不知道的 5 件事。
4. 挖不到作者理由的节点标 `[素材不可判]`：照样能练决策，但**不进偏差档案**。

## 4. held-out 设计（L3 唯一的"学会了没有"判据）

利用制卡/跑卡天然分离：**指定你还没读的两章为盲测区**，AI 从中出卡，你不许提前打开原文。

- 候选盲测区：**「透明多级分流系统」** + **「架构安全性」**（你目前主线还没覆盖，泄底风险最低）
- 跑法：隔 ≥2 周，各盲跑 3 个节点，记下选对率
- 判读：选对率相对链路 A/B 明显上升 → 蒸出的是策略；持平 → 说明前面蒸进的是事实记忆，回炉
- 禁止：盲跑前查那两章的正文、评论、二手解读

## 5. 缺口与禁止项

| 项 | 状态 | 处理 |

| 样例工程真实仓库名 | 本轮只核实到"在独立仓库"，未定位 | [挖不到]，不许凭记忆写仓库名 |
| 作者写作决策的自述密度 | 未知。前言/博客可能有，也可能全无可挖 | A1–A5 逐节点先挖再判；判不了就 [素材不可判] |
| 在线版 vs 纸质版差异 | 在线版在维护（v1.0.20260928） | 引用一律带版本号；差异本身是 A6 的素材 |
| 许可证 | 文本 CC BY-NC-SA 4.0，代码 Apache 2.0 | 不许改写正文后商用；内部学习可用 |
| 规模错配 | 书的样例是教学工程，非生产系统 | 走 L1 降温层：照搬结论前先问"我这 10 人团队付得起吗" |
| 把"书里这么写"当决策依据 | — | 禁止。书是二级信源，进 citation 只允许作为锚点，不允许作为机制证明 |

## 6. 节奏

1. 先做 **A6 前置**：拉 commit 历史建 `commit索引.md`——这一步决定链路 A 能不能跑，其他都可以跳过它但跳不过这步。
2. 出 **A1（主轴选择）** 一张卡：它是全书的性格原点，且负向推理最密。
3. 出 **A4（重写五遍）** 一张卡：直接咬合 dsh 主线。
4. 每次只过 1 个节点，保持"先决策"的张力。
5. 累积 10+ 节点后开 `../../经历蒸馏/偏差档案.md`，按准入三条聚类。
6. 链路 B 排在 A 之后——它需要先确认你不会因读过演进史那章而泄底。
