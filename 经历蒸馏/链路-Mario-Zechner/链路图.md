## 状态继承链（为什么不能跳着跑）

```
N1 触发点（对 Claude Code 类工具的不满程度）
      └─→ N2 极简定位（不满越深，"不要什么"清单越长）
              └─→ N3 工具预算（<1000 token 是一切功能的准入考试）
                      └─→ N4 拒绝 MCP（token 开销 = 原反对理由）
                              └─→ N5 被收购（资源约束突变）
                                      └─→ N6 MCP 反转（必须处理"我公开说过反话"的信誉成本）
```

关键：**N6 的反转代价是被 N4 抬高的**——如果当初没公开拒绝，反转只是技术调整；公开拒绝过，反转就是立场修正。跑 N6 时必须带着 N4 的后果。

## 每条节点的开放问题（节点卡要回答的）

- N1：一个成名的独立开发者（libGDX 已成功），什么触发他 All in 一个新领域？是负向（对现有工具失望）还是正向（看到机会）？
- N2：负向推理的完整清单——他具体在拒绝 Claude Code 的哪些东西？（功能膨胀/提示词漂移/上下文黑盒，各对应什么痛）
- N3：为什么是这 4 个工具？砍掉 bash 之外的执行能力，用户怎么活？
- N4：拒绝 MCP 的论证链——token 开销具体怎么算的？
- N5：独立开发者被收购，通常失去什么、得到什么？他的决策模型里哪个权重更高？
- N6：**核心问题**——什么条件变了，让 10 个月前的反对理由失效？（Codemode 的 JS 沙箱是否精准解决了 token 开销？还是资源/战略变化？）
- N7：MIT + 全功能免费，11 万星怎么不变成沉没成本？
