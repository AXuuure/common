## 分析

**这篇解决什么问题**：第二课评的是"一个类别"，本课把视角抬到"十个类别的整体系统"，讲清混淆矩阵怎么读，以及 Micro 与 Macro 两套聚合口径各自会掩盖什么。

**核心结论**

1. **Micro 按次算、Macro 按类算**：Micro 让每一次预测权重相同，因此高频类别主导结果；Macro 让每个类别权重相同，用来暴露被忽略的小类。选错口径，结论会反过来。
2. **单标签多分类下 Micro 会退化**：每个分类错误同时产生一个 FP 和一个 FN，于是
   `Micro-Precision = Micro-Recall = Accuracy = Micro-F1`。例中四类别全为 75%。所以 Micro-Fβ 在这种场景下没有额外价值——作者明确写了这句，很多人会白算一遍。
3. **要看漏报和误报的真实分布，必须回到各类别自己的 Recall / Precision**，或看 Macro。文中账单争议 Recall 只有 60%，意味着真实账单争议被漏掉 40%，而这个信息在 Micro 里被平均掉了。
4. **Macro-F1 ≠ 用 Macro-P 和 Macro-R 再算一次 F1**：前者是各类别 F1 的平均，后者会因平均后再取调和而给出不同数字。这是实操里最常见的口径错误之一。
5. **混淆矩阵的正确用法是一套动作，不是一个数字**：找非对角线最大格 → 判断错误方向与业务成本 → 看该格原始问题 → 改类别定义与边界案例 → 补 Prompt 或 RAG 对比样本 → 把错误样本加入回归测试 → 重算所有指标。例中最大错误簇是"实际账单争议 → 预测账单咨询"共 2 条，指向的正是第一课说明卡里"是否要求纠正收费"这条边界。
6. **看矩阵时三种视图各有用途**：原始数量判断错误规模；按行归一化看 Recall 与漏识别方向；按列归一化看 Precision 与误报来源。
7. **β 必须按业务成本定，不能为了刷分调**：文末给了映射表（各类别漏报成本高 → Macro-F2；误报成本高 → Macro-F0.5；同等重要 → Macro-F1；只有一个类别不能漏 → 该类别 Recall 或 F2）。

**作者自己加的预警（原文 callout）**：Macro 用的是普通算术平均，当某个类别得分特别低时仍会被平均掩盖；可选做法是改用 Macro 的调和平均，即
`H-Mean(Class-F1) = K ÷ Σ(1 ÷ F1)`。这是本篇最有工程价值的一条补丁——它把"调和平均防偏科"的逻辑从类别内部（第二课 F1）推广到了类别之间。

**缺口与存疑**

- 混淆矩阵只有 4 个类别 × 20 条样本，是教学规模；真实十类别场景下矩阵稀疏性和每格样本量都是问题。
- 未涉及类别不均衡下的采样与加权评测、以及多标签场景（一句话多个意图）如何扩展 Micro/Macro——而第一课的策略二恰恰会产出多标签结果，两课之间这里有个未闭合的口子。

### 1.1 混淆矩阵

混淆矩阵展示：

> 实际类别是什么，模型最终预测成了什么。

- 行：实际类别
- 列：模型预测类别
- 对角线：预测正确
- 非对角线：预测错误

（原文内嵌表格 `OGaNyO`）

| 实际 ↓ / 预测 → | 理赔争议 | 理赔协助 | 账单争议 | 账单咨询 |
|---|---|---|---|---|
| 理赔争议 | 4 | 0 | 1 | 0 |
| 理赔协助 | 1 | 4 | 0 | 0 |
| 账单争议 | 0 | 0 | 3 | 2 |
| 账单咨询 | 0 | 0 | 1 | 4 |

对角线正确数：

```Plain Text
4 + 4 + 3 + 4 = 15
```

非对角线错误数：

```Plain Text
1 + 1 + 2 + 1 = 5
```

最大错误簇：

```Plain Text
实际：账单争议
预测：账单咨询
数量：2
```

说明模型容易混淆：

- 询问收费原因
- 认为收费错误并要求纠正

使用混淆矩阵时：

1. 找到非对角线最大的错误格。
2. 判断错误方向和业务成本。
3. 查看该格对应的原始问题。
4. 修改类别定义和边界案例。
5. 补充 Prompt 或 RAG 对比样本。
6. 将错误样本加入回归测试。
7. 修改后重新计算所有指标。

建议查看：

- 原始数量：判断错误规模
- 按行归一化：观察 Recall 和漏识别方向
- 按列归一化：观察 Precision 和误报来源

### 1.2 Micro 次数维度，看整体

> Micro：整体做得怎么样，高频类别影响更大。按次算。
> Macro：每个类别做得怎么样，所有类别权重相同。按类算。

#### 1.2.1 Micro-Precision

Micro-Precision 让每一次预测拥有相同权重；

先汇总所有类别的 TP 和 FP，再计算 Precision：

```Plain Text
Micro-Precision
= ΣTPᵢ ÷ (ΣTPᵢ + ΣFPᵢ)
```

它回答：

> 从所有模型预测结果来看，整体有多少是正确的？

举例

```Plain Text
ΣTP = 15
ΣFP = 5

Micro-Precision
= 15 ÷ (15 + 5)
= 75%
```

最佳实践

适合判断整体预测结果的可信程度。

但在单标签多分类中，它通常等于 Accuracy，不能反映具体哪个类别误报严重。

#### 1.2.2 Micro-Recall

先汇总所有类别的 TP 和 FN，再计算 Recall：

```Plain Text
Micro-Recall
= ΣTPᵢ ÷ (ΣTPᵢ + ΣFNᵢ)
```

它回答：

> 从所有实际存在的正确标签来看，模型整体找回了多少？

举例

```Plain Text
ΣTP = 15
ΣFN = 5

Micro-Recall
= 15 ÷ (15 + 5)
= 75%
```

最佳实践

适合观察整体漏识别情况。

但在单标签多分类中，每一个分类错误都会同时产生一个 FP 和一个 FN，因此：

```Plain Text
Micro-Precision
= Micro-Recall
= Accuracy
```

如果关心某个重要类别是否被漏掉，应该查看该类别自己的 Recall。

#### 1.2.3 Micro-F1

Micro-F1 平衡 Micro-Precision 和 Micro-Recall：

```Plain Text
Micro-F1
= 2 × Micro-Precision × Micro-Recall
  ÷
  (Micro-Precision + Micro-Recall)
```

它回答：

> 把所有问题放在一起看，系统整体分类表现怎么样？

举例

```Plain Text
Micro-Precision = 75%
Micro-Recall = 75%

Micro-F1
= 2 × 0.75 × 0.75 ÷ (0.75 + 0.75)
= 75%
```

当前是单标签多分类，所以：

```Plain Text
Micro-F1 = Accuracy = 75%
```

最佳实践

适合：

- 衡量整体流量效果
- 比较模型或 Prompt 版本
- 设置发布门槛
- 监控线上整体质量

但大类别对 Micro-F1 的影响更大，可能掩盖小类别的问题。

#### 1.2.4 Micro-Fβ

Micro-Fβ 可以调整 Precision 和 Recall 的重要程度：

```Plain Text
Micro-Fβ
= (1 + β²) × Micro-Precision × Micro-Recall
  ÷
  (β² × Micro-Precision + Micro-Recall)
```

- `β = 1`：同等重视 Precision 和 Recall
- `β > 1`：更加重视 Recall
- `β < 1`：更加重视 Precision

举例

假设：

```Plain Text
Micro-Precision = 80%
Micro-Recall = 50%
```

则：

```Plain Text
Micro-F1 = 61.5%
Micro-F2 = 54.1%
Micro-F0.5 = 71.4%
```

由于 Recall 较低，所以更重视 Recall 的 Micro-F2 会给出更严格的分数。

但在当前案例中：

```Plain Text
Micro-Precision = Micro-Recall = 75%
```

因此：

```Plain Text
Micro-F0.5
= Micro-F1
= Micro-F2
= 75%
```

最佳实践

Micro-Fβ 更适合：

- 多标签分类
- Micro-Precision 和 Micro-Recall 不相等
- 整体误报与漏报成本不同

标准单标签多分类中，Micro-Fβ 通常没有太多额外价值。

### 1.3 Macro 分类维度，看分类

> ⚠️ 原文提示框：注意，这里的指标用的是通用的平均数，也容易出现单个分类得分很低的时候被忽略的情况。可以用 Macro 的调和平均算法来做。
>
> `H-Mean(Class-F1) 可选预警 = K ÷ Σ(1 ÷ F1ᵢ)`

#### 1.3.1 Macro-Precision

先计算每个类别自己的 Precision，再取平均：

```Plain Text
Macro-Precision
= (P₁ + P₂ + … + Pₖ) ÷ K
```

它回答：

> 平均来看，每个类别的预测结果有多可信？

每个类别拥有相同权重。

举例（原文内嵌表格 `lk5hab`）

| 类别 | Precision |
|---|---|
| 理赔争议 | 80% |
| 理赔协助 | 100% |
| 账单争议 | 60% |
| 账单咨询 | 66.70% |

```Plain Text
Macro-Precision
= (80% + 100% + 60% + 66.7%) ÷ 4
= 76.7%
```

最佳实践

适合检查是否有某些类别误报严重。

但平均数仍然可能掩盖单个差类别，所以还要查看各类别 Precision。

#### 1.3.2 Macro-Recall

先计算每个类别自己的 Recall，再取平均：

```Plain Text
Macro-Recall
= (R₁ + R₂ + … + Rₖ) ÷ K
```

它回答：

> 平均来看，每个类别实际存在的问题被找回了多少？

举例（原文内嵌表格 `LLdMqc`）

| 类别 | Recall |
|---|---|
| 理赔争议 | 80% |
| 理赔协助 | 80% |
| 账单争议 | 60% |
| 账单咨询 | 80% |

```Plain Text
Macro-Recall
= (80% + 80% + 60% + 80%) ÷ 4
= 75%
```

账单争议 Recall 只有 60%，说明真实的账单争议被漏掉了 40%。

最佳实践

Macro-Recall 适合：

- 检查各类别整体漏识别情况
- 类别数量不均衡的任务
- 每个类别都不能被忽略的场景

在单标签多分类中，Macro-Recall 也常被称为"平衡准确率"。

#### 1.3.3 Macro-F1

先计算每个类别自己的 F1，再进行平均：

```Plain Text
Macro-F1
= (F1₁ + F1₂ + … + F1ₖ) ÷ K
```

它回答：

> 每个类别的 Precision 和 Recall 综合表现是否均衡？

举例（原文内嵌表格 `PPoFRv`）

| 类别 | Precision | Recall | F1 |
|---|---|---|---|
| 理赔争议 | 80% | 80% | 80.00% |
| 理赔协助 | 100% | 80% | 88.90% |
| 账单争议 | 60% | 60% | 60.00% |
| 账单咨询 | 66.70% | 80% | 72.70% |

```Plain Text
Macro-F1
= (80.0% + 88.9% + 60.0% + 72.7%) ÷ 4
= 75.4%
```

最佳实践

Macro-F1 适合：

- 检查小类别是否被忽略
- 判断各类别是否均衡
- 类别样本数量差距较大的任务
- 防止模型只优化高频类别

注意：

```Plain Text
Macro-F1
= 各类别 F1 的平均
```

通常不等于：

```Plain Text
用 Macro-Precision 和 Macro-Recall 再计算一次 F1
```

#### 1.3.4 Macro-Fβ

先计算每个类别自己的 Fβ，再进行平均：

```Plain Text
Fβᵢ
= (1 + β²) × Pᵢ × Rᵢ
  ÷
  (β² × Pᵢ + R)

Macro-Fβ
= (Fβ₁ + Fβ₂ + … + Fβₖ) ÷ K
```

它同时实现：

- Macro：每个类别拥有相同权重
- Fβ：调整误报和漏报的重要程度

举例

如果更加担心漏识别，使用 `β = 2`（原文内嵌表格 `kKUAEM`）：

| 类别 | Precision | Recall | F2 |
|---|---|---|---|
| 理赔争议 | 80% | 80% | 80.00% |
| 理赔协助 | 100% | 80% | 83.30% |
| 账单争议 | 60% | 60% | 60.00% |
| 账单咨询 | 66.70% | 80% | 76.90% |

```Plain Text
Macro-F2
= (80.0% + 83.3% + 60.0% + 76.9%) ÷ 4
≈ 75.1%
```

最佳实践（原文内嵌表格 `CF6dNv`）

| 业务需求 | 推荐指标 |
|---|---|
| 各类别漏报成本更高 | Macro-F2 |
| 各类别误报成本更高 | Macro-F0.5 |
| 误报、漏报同等重要 | Macro-F1 |
| 只有一个类别不能漏 | 该类别 Recall 或 F2 |

β 应根据业务成本确定，不能为了提高分数而调整。
